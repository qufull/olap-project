## 1. Под какой виджет дашборда спроектирована сводка (З10)

Сводная таблица спроектирована под главный динамический график аналитического дашборда Metabase:
* **Название виджета:** *«Динамика выручки (Net GMV) и выполненных заказов по дням в разрезе районов и тарифов»*.
* **Тип визуализации:** Stacked Area Chart (диаграмма с областями) / Multi-line Chart.
* **Назначение:** Позволяет операционному директору и логистам отслеживать структуру спроса по тарифам (Экспресс / Стандарт / Эконом) во времени с фильтрацией по конкретным районам города, не сканируя 600 000 строк детальной таблицы при каждом клике.

---

## 2. Что означает одна строка сводной таблицы

> **Одна строка сводной таблицы (`agg_daily_district_tariff`) = календарный день (`order_date`) × район (`district_id`) × тариф доставки (`tariff`).**

### Принципиальное различие зёрен:
* **Зерно детальной таблицы (`fact_orders`):** одна строка = **один отдельный оформленный заказ** клиента со своим уникальным `order_id` (всего 600 000 строк).
* **Зерно сводки (`agg_daily_district_tariff`):** одна строка = **суточный агрегат доставленных заказов** одного тарифа в одном районе города (всего 13 140 строк — сжатие в 41.1 раза!).

## 3. Какие суммы лежат в сводке

Все показатели строго соответствуют каноническому эталону метрик из `sql/canonical_metric.sql` (учитываются только выполненные заказы со статусами `'Доставлен'` и `'Опоздание'`):

| Колонка сводки | Тип данных | Описание и способ расчёта |
| :--- | :--- | :--- |
| `order_date` | `Date` | Дата совершения заказов (ключ сортировки) |
| `district_id` | `Int32` | Внешний ключ района доставки |
| `tariff` | `String` | Тариф: `Экспресс`, `Стандарт`, `Эконом` |
| `delivered_orders_cnt` | `UInt32` | Суммарное число доставленных заказов за день (`count(order_id)`) |
| `net_gmv_byn` | `Decimal(14, 2)` | Валовой оборот доставленных заказов (`sum(total_amount)`) |
| `platform_commission_byn`| `Decimal(12, 2)`| Комиссионный доход Яндекс Доставки (`sum(platform_commission)`) |
| `delivery_revenue_byn` | `Decimal(12, 2)`| Базовая выручка от платной доставки (`sum(delivery_fee)`) |
| `surge_revenue_byn` | `Decimal(12, 2)`| Выручка за повышенный динамический спрос (`sum(surge_fee)`) |
| `courier_payout_byn` | `Decimal(12, 2)`| Суммарные выплаты курьерам за смену (`sum(courier_payout)`) |

## 5. Как пересчитать сводку после повторной загрузки данных

1. **Автоматический инкрементальный режим (ClickHouse Materialized View):**
   При потоковой вставке новых заказов представление `mv_daily_district_tariff` непрерывно направляет и сворачивает агрегированные пачки в движок `SummingMergeTree`.
2. **Пакетная перезагрузка (Batch ELT):**
   При полном обновлении сырых CSV запускается единая команда пересчёта:
   ```bash
   python _stand/scripts/build_summary_mv.py
   ```
   Внутри выполняется транзакционный `TRUNCATE TABLE agg_daily_district_tariff` и повторный `INSERT ... SELECT`, что полностью исключает дублирование записей и сохраняет абсолютную идемпотентность контура.
