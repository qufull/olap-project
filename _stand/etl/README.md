# З05. ELT-пайплайн и проверки качества (`etl/`)

## Что делает скрипт `etl/elt_pipeline.py`
1. **Staging (`stg_*`):** Читает сырые CSV-файлы из `data/raw/` во временные таблицы в памяти (`stg_users`, `stg_restaurants`, `stg_couriers`, `stg_orders`).
2. **Проверки качества (Data Quality Gates):** До записи в чистовые таблицы проверяет данные на:
   - отсутствие `NULL` в ключевых полях, датах, суммах и статусах;
   - допустимый диапазон (`total_amount > 0`, `delivery_time_minutes > 0` для доставленных, даты в пределах `2025–2026` гг.);
   - отсутствие дубликатов первичного ключа `order_id`;
   - отсутствие «сирот» (`orphan keys` — заказов с `user_id`, `restaurant_id` или `courier_id`, которых нет в справочниках).
   *Если хотя бы одна проверка находит `> 0` проблемных строк, скрипт выбрасывает `RuntimeError` и аварийно останавливает загрузку (`sys.exit(1)`).*
3. **Порядок загрузки:** Внутри единой транзакции (`BEGIN ... COMMIT`) строго **сначала** загружаются справочники (`dim_users`, `dim_restaurants`, `dim_couriers`, `dim_date`), и **только после них** — таблица фактов (`fact_orders`).

## Стратегия повтора (идемпотентность)
> **Что чистим при повторе:** При каждом перезапуске после успешного прохождения проверок качества скрипт выполняет полную очистку целевых таблиц (`TRUNCATE TABLE fact_orders, dim_users, dim_restaurants, dim_couriers, dim_date`) внутри транзакции перед повторной вставкой данных, поэтому второй и последующие прогоны не удваивают продажи.

## Как запустить
Из папки `_stand`:
```bash
python etl/elt_pipeline.py
